Pocono AI Sentinel Node Training Installer Simulation

Operator-facing training for governed local AI deployment.

This simulator walks through how Sentinel Node is deployed into a regulated practice environment: network discovery, subnet/VLAN planning, firewall boundaries, appliance setup, approved-source loading, human review, audit verification, and go-live readiness.

  • Who it's for Built for installers, MSPs, internal IT teams, and practice-side stakeholders.
  • What it shows Local-first AI deployment with approved sources, human review, and auditability.
  • What it is Training simulation only — authorized IT/MSP personnel remain responsible for real network configuration.

Guided mode auto-advances at a deliberately slow Training Pace (you can speed it up or slow it down with the − / + controls, or pause at any time). Manual mode never auto-advances. Configuration Practice lets you rehearse an install and run verification. Preflight & Install Emulator runs a stateful checklist and a step-by-step deployment with an integrated report.
This is a beta training artifact — not a substitute for site-specific security review.

Pocono AI Configuration Practice

Configuration Practice — Install Rehearsal

Scenario. You are installing Sentinel Node in a small clinic or regulated office. The existing office LAN is 192.168.1.0/24. Patient Wi-Fi and guest Wi-Fi are present. Sentinel Node must be placed on an isolated subnet/VLAN with controlled access, approved-source loading, human review, audit logging, and a go-live report. Configure the deployment below, then Run Verification to see PASS / WARNING / CRITICAL findings and a go-live readiness decision.
Training notes — audit & citations
  • Citations support human review — they do not prove the AI interpretation is correct. Sentinel Node returns a cited draft; a qualified person reviews before clinical, legal, or operational use.
  • Pilot mode uses a reviewable, exportable audit trail. Tamper-evident hash chaining and signed verification bundles are planned for the next audit-layer release (Stage 2).
  • Do not deploy if human review can be bypassed, or if audit logging is disabled — the audit record would be incomplete.
  • Needs review if the approved-source version is not recorded.
  • Switch Verify audit against to Stage 2 (Group G) to evaluate the tamper-evident hash-chained layer; in pilot mode, missing hash chaining is a roadmap note, not a failure.
