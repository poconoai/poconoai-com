# Z2.01 — Veteran Node Ecosystem Intelligence Layer

**Base package:** Z2.00 Veteran Node Product Lane
**Date:** 2026-06-27
**Scope:** Software only (`apps/api/sentinel`, `ui/index.html`, `demo_data/`, `tests/`). PoconoAI.com was not touched.

---

## 1. Summary

Z2.01 turns Veteran Node from a personal orientation workspace into an early
**Ecosystem Intelligence Layer**, built on three primitives: **Action Cards**,
**Governance Receipts**, and **Trusted Handoffs**. It is additive to Z2.00 —
nothing in the existing product lane, role model, workflow templates, or
research-chat boundary was renamed, weakened, or removed.

The MVP loop works end-to-end against real (synthetic) data, not mocked
output: the deterministic engine loads the synthetic ecosystem fixtures,
detects a next-best-action, produces an Action Card with confidence/urgency/
evidence/boundaries, a human reviews it, and if it involves another party it
becomes a Trusted Handoff that requires consent before introduction and
carries its own Governance Receipt with full status history.

Everything is rule-based and deterministic — no live LLM call, no live web
search, no email/calendar monitoring, no grant crawling, no autonomous
outreach. Trusted Handoffs use an in-memory demo store (the same pattern
`guided_experience.py` already uses for golden-path demo runs), seeded from
the synthetic fixtures, so the workflow is genuinely interactive in this
cycle without requiring a new database table.

All data is synthetic. The existing Jordan Hale persona was kept and extended
with two new synthetic personas, six organizations, four trusted businesses,
four funding opportunities, four volunteer needs, six referral handoffs, and
the eight required ecosystem-signal scenarios — every one of which the live
engine independently re-detects from the raw fixtures (it doesn't just echo a
canned list).

## 9. Remaining risks

- **In-memory handoff store, not yet persisted.** `veteran_handoff_workflow.py`
  keeps Trusted Handoffs in a process-local dict, per the build spec's explicit
  permission to defer persistence this cycle. Restarting the API process
  resets any handoff created or modified during the session (the seeded
  fixture handoffs reappear in their original synthetic state). The module
  is structured so a future cycle can swap the dict for a real table without
  changing any caller (every function already takes/returns plain dicts).
- **Rule-based matching, not semantic.** Region/category/eligibility matching
  in the engine uses substring/keyword heuristics, not embeddings or an LLM.
  This keeps it fully deterministic and explainable (a stated goal), but it
  will miss matches phrased very differently from the fixture's keyword set.
  Confidence levels are calibrated to reflect this (a thin/keyword-only match
  never reports "high" confidence).
- **Consent model is a flag, not a full audit trail of who-granted-what-when
  beyond the handoff's own status history.** Sufficient for this cycle's
  scope; a real deployment would want a dedicated consent ledger, which is
  exactly what Cycle 2 of the broader Steward Layer roadmap should add.
- **Negation-aware prohibited-phrase check is clause-scoped, not fully
  semantic.** It correctly distinguishes "does not conduct surveillance"
  from "conducts surveillance on…", but a sufficiently convoluted sentence
  could in principle still slip past or get incorrectly blocked. It's a
  defense-in-depth check, not the only safeguard — every Action Card still
  requires human review regardless.

## 10. Recommended Z2.02 next step

Per the build spec's own Cycle 2/3 roadmap (not built this cycle, by design):

1. **Persistence** for Trusted Handoffs and Governance Receipts (a real
   table, replacing the in-memory store) so demo state survives a restart
   and multiple users can interact with the same ecosystem concurrently.
2. **A dedicated consent ledger** — who granted consent, for what, when, and
   under what scope — rather than a single boolean on the handoff record.
3. **Explicitly authorized connectors** (calendar/email/docs) behind the
   same approval gate already used elsewhere in this codebase, replacing the
   manual-import-only posture of this cycle — still no live web crawl, no
   unsupervised outreach.
4. A small **UI polish pass**: a dedicated nav view for the ecosystem panel
   (today it's appended below the existing Veteran Node quick actions,
   which works but isn't a first-class navigable tab yet), and richer
   Action-Card → Trusted-Handoff promotion (today a human still creates the
   handoff manually via the API; the next step is a one-click "turn this
   Action Card into a Trusted Handoff" button on the card itself).
