Trust Stack

Five layers. One promise. Zero compromise.

Hardware → Inference → Governance → Human oversight → Append-only audit. Each layer reinforces the one above. Remove any layer and the stack fails. Pocono AI enforces all five structurally.

Implementation Status Sentinel Node v1.46 · Sessions Z1–Z21 · release-candidate scaffold

The current internal package implements the control-plane scaffolding for the architecture described here.

An internal release-candidate build sequence has turned the layers above into working control surfaces: regulated-mode authentication, patient and matter scope boundaries, OCR confidence gating, evidence-train checks, local retrieval scaffolding, local LLM routing through the Audit Proxy, signed update custody, golden-case regression, professional packet export, compliance evidence mapping, and local-only metrics. This is a pilot-candidate scaffold, not a production certification. Professional review remains mandatory.

Retrieval

A local deterministic retrieval engine is the current default. Qdrant and production retrieval remain deployment-configurable — the migration path runs from deterministic retrieval through dense embeddings, hybrid BM25, and reranking, validated against golden cases.

Generation

The application never calls a model provider directly. Local LLM providers are routed through the Audit Proxy, where provider policy, local-only restrictions, model allowlisting, bounded context, and draft-only safety envelopes are enforced. No direct app-to-LLM path exists.

Connectors

External connectors are governed and disabled or dry-run by default unless a customer-specific binding is configured and validated. Controlled folder ingestion preserves scope and label metadata through indexing.

OS & Custody Boundary

VLAN, firewall, USB policy, and disk encryption remain installer and MSP responsibilities, enforced outside the application layer. The application verifies what it can see; the installer and MSP enforce operating-system controls.

Not every production connector and model is complete. The package implements the control-plane scaffolding; production retrieval, enterprise identity bindings, and external connectors remain deployment-configurable and require customer-specific review.

Audit & Security Roadmap Reviewable today Tamper-evident next

Reviewable Today. Tamper-Evident Next.

Sentinel Node’s pilot architecture preserves a reviewable audit trail for approved-source retrieval, draft generation, human review, and go-live reporting. We do not claim that citations prove correctness, or that a local log is tamper-proof. Our next audit-layer release adds hash-chained audit events, signed verification bundles, admin-action logging, and optional off-box/WORM retention for stronger tamper-evidence.

Citations support human review — they do not prove the AI’s interpretation is correct. Sentinel Node produces cited draft output from approved sources; a qualified person reviews before any clinical, legal, or operational use. “Tamper-evident” here means alteration is detectable, not impossible.

1. The Ingest Path

  • Service: Local background daemon, strictly no outbound network access.
  • Source: Watches a designated customer-controlled SMB share (we never host your PHI).
  • Security: Strict file whitelist (.pdf, .txt, .xml, .docx).

2. Cryptographic Lifecycle

  • Pipeline: Copy → SHA-256 Hash → Index → Write Audit Log → Secure Wipe (single-pass zero overwrite, then unlink).
  • Failure Path: Unreadable files route to /quarantine for 72h, alert the admin, then auto-purge.
  • Capacity Guard: 5GB default circular buffer, oldest-first eviction with a logged entry.

3. What We DON'T Do

  • No persistent copies left in the watch folder.
  • No cloud staging or external API routing.
  • No background telemetry during ingestion.
Data Retention Policy: Audit logs are retained for 90 days. Source files are securely deleted immediately post-ingest (an optional 7-day encrypted hold is available for legal compliance routing).

05 · Document Sanitization Pipeline

We do not blindly ingest bad data. Before any document reaches the RAG vectorization layer, it passes through a local preprocessing pipeline designed to enforce data quality and protect the integrity of every AI output.

Phase 00 · Local OCR Microservice

Every document — including scanned faxes, handwritten notes, and legacy PDFs — is processed through a locally hosted OCR engine (Tesseract / NVIDIA Ada vision pipeline) before vectorization. No document is assumed to be machine-readable until verified.

Confidence Scoring & Quarantine

Each extraction is scored for OCR confidence. Documents falling below the 95% extraction threshold are refused by the vectorizer and routed to a secure Quarantine Dashboard for manual human review — substantially reducing the risk of unreliable outputs from corrupted source data.

The Guarantee

The Sentinel Node is designed to refuse ingestion of low-confidence scans. If a fax is unreadable, the system refuses to ingest it and flags it for staff verification. Clean data in. Cited, auditable answers out.

06 · Operational Continuity Architecture

A sovereign deployment is only as strong as its uptime guarantee. Pocono AI engineers operational continuity through structural redundancy and enterprise hardware infrastructure — not through the physical presence of a technician. Because each deployment operates autonomously within a single facility, continuity is a local property: no upstream dependency on a regional data center or cloud availability zone.

Active-Passive Twin Node Model

Enterprise deployments configure two nodes in a high-availability active-passive cluster. If the primary node experiences a hardware fault, the passive node absorbs the query load seamlessly — with zero workflow interruption to clinical or legal staff.

Dell Enterprise Technology Stack

The Sentinel Node is built on Dell Precision hardware, designed to leverage Dell ProSupport Plus — 4-hour on-site parts and labor from Dell's global logistics network. Pocono AI acts as the software and RAG layer; Dell's enterprise support infrastructure serves as the physical continuity arm. Support coverage is scoped per deployment during the architecture assessment phase.

The Guarantee

"Pocono AI engineers for workflow continuity not by rushing a technician to your clinic, but through local active-passive redundancy backed by an enterprise hardware support SLA." This is continuity by architecture, not heroics.

For IT & MSPs: Network Deployment Specification

The Sentinel Node is designed to be set up by a regional Managed Service Provider (MSP) in a single afternoon. No specialized AI expertise is required. The following specifications define exactly what your IT partner needs to configure.

Step 1 — VLAN Isolation

Create a dedicated VLAN for the Sentinel Node segment. The node requires inbound LAN access from authorized clinical workstations only. All outbound internet routes are blocked at the VLAN boundary. A standard managed switch with VLAN tagging (802.1Q) is sufficient — no specialty hardware required.

Step 2 — Local Drop-Folder

A secure local share is configured on the practice's existing LAN. Staff export PDFs from the EHR to this folder using their normal workflow. The Sentinel Node monitors the folder and indexes new documents automatically. No USB transfers per document. No manual file moves per query.

Step 3 — Update Verification

Software and model weight updates are never pushed over the internet. LLM weights, RAG enhancements, and security patches are delivered as cryptographically signed packages (Ed25519 signature + SHA-256 checksum). The IT administrator receives the package, verifies the hash against the value published in the Secure Client Portal, and physically applies it via signed USB. Unsigned or hash-mismatched USB media is automatically rejected — the Sentinel Node will not mount or execute an unverified package under any circumstances.

⊘ Never Over the Network
  • No remote push updates
  • No vendor management tunnel
  • No automatic cloud sync
✓ Physical-Only Update Path
  • Ed25519-signed package required
  • SHA-256 hash verified before install
  • Every update logged to append-only audit trail
