Sentinel Node · Pilot-Scaffold Update

Sentinel Node has moved from architecture to pilot-candidate control plane.

Pocono AI has completed an internal release-candidate build sequence for Sentinel Node's governed local evidence workflow. The package now includes regulated-mode authentication, patient and matter scope boundaries, OCR confidence gating, evidence-train checks, local retrieval scaffolding, local LLM routing through the Audit Proxy, signed update custody, golden-case regression, professional packet export, compliance evidence mapping, local-only metrics, and first-pilot configuration templates.

Professional review remains mandatory. This is a pilot-candidate scaffold, not a production certification.

Internal build: Sentinel Node v1.46 Sequence: Z1 → Z21 Posture: release-candidate pilot scaffold Date: May 27, 2026
What this update is not Sentinel Node is not HIPAA compliance certified, not legal-compliance certified, not NIST-certified, not ISO 42001 certified, and not certified for production deployment. The system does not replace physician judgment or attorney judgment, does not guarantee payer approval or legal outcome, and cannot prove hallucinations impossible. It provides evidence-bound controls — retrieval citations, unsupported-claim warnings, draft review, named approval, export gates, drift monitoring, and audit envelopes — that a licensed professional reviews before any regulated output moves forward.
01

What the pilot scaffold now contains

Eight capability surfaces moved out of architecture documentation and into the working internal package. Each remains framed for supervised pilot evaluation — not blind automation.

Identity & Access

Regulated authentication

Regulated mode, named users, role mapping, and break-glass posture. Required before real pilot data.

Evidence Integrity

OCR gate & evidence train

OCR confidence threshold, admissibility status, evidence train, and citation mapping. Low-confidence material is refused or routed to manual review.

Retrieval & Generation

Local retrieval; local LLM through Audit Proxy

Local deterministic retrieval engine with optional Qdrant seam. Local LLM generation flows only through the Audit Proxy — no direct app-to-LLM path.

Professional Workflows

Workflow template library

Prior authorization, denial appeal, medical necessity summary, legal chronology, matter memo, discovery summary, and evidence packet templates.

Export & Audit

Professional packet export

Professional packet export with evidence appendix, audit envelope, manifest, and checksums. Markdown, HTML, and JSON artifacts are the default safe path.

Deployment Custody

Signed updates & trusted keys

Signed offline update workflow, trusted release keys, rollback checks, and signed USB media verification.

Pilot Operations

Golden cases & drift watch

Golden-case regression harness, drift monitoring, model refresh thresholds, local-only metrics dashboard, and redacted support bundles.

Readiness Artifacts

Pilot configuration packs

Physician pilot configuration template, law-firm pilot configuration template, MSP deployment guide, and compliance evidence binder.

Architecture vs. configured surface

The current internal package implements the control-plane scaffolding for the architecture described elsewhere on this site. Production retrieval (Qdrant), enterprise identity bindings, and external connectors remain deployment-configurable. External connectors ship governed, disabled, and dry-run by default. Operating-system controls — VLAN, firewall, USB policy, disk encryption — remain installer and MSP responsibilities, enforced outside the application layer.

02

Governance is runtime, not paperwork

Governance is not a PDF afterthought. In Sentinel Node, governance is expressed as runtime gates: OCR confidence, evidence admissibility, scope filtering, draft quality review, professional approval, export blocking, signed update custody, and local audit envelopes. Each gate produces an auditable signal a reviewer can inspect.

The new package adds the operational surfaces that turn those gates from policy language into observable controls — named reviewer fields, evidence-train checks, draft-quality and unsupported-claim monitoring, drift watch, model refresh thresholds, golden-case regression, a local metrics dashboard, and a compliance evidence binder that maps controls to the questions auditors and counterparties actually ask.

03

Deployment custody and OS boundary

The application verifies what the application can see. The installer and MSP enforce operating-system controls such as firewall rules, USB policy, disk encryption, systemd hardening, and physical custody. The boundary is intentional — it keeps the application honest about what it actually controls.

The package now ships with appliance installer artifacts, a hardening check script, trusted release keys, a signed update workflow, USB and update-media policy, a backup and restore plan, and a redacted support-bundle posture. Together they let an MSP review the deployment against a concrete artifact list rather than a brochure.

04

First-pilot configuration packs

Two synthetic configuration templates ship with the release-candidate package: one physician-office profile and one law-firm profile. Both use synthetic names, synthetic scopes, and synthetic import paths. They are reference templates, not automatic provisioning. Real users, scopes, labels, and identity bindings remain a customer and MSP decision — reviewed at pilot kickoff against the data-handling checklist and role worksheet.

Physician Office Profile

Prior auth, denials, medical-necessity summary

Workspace profile physician. Regulated mode required before real data. Controlled folder ingestion with PHI labels. Clinician approval gates exports. Patient-scope isolation prevents cross-patient retrieval.

Law-Firm Profile

Chronology, matter memo, discovery summary

Workspace profile attorney. Regulated mode required before real data. Matter-scope isolation prevents cross-matter retrieval. Privileged and confidential labels gate evidence use. Attorney approval gates exports.

Pilot configuration rules in effect

Synthetic data first. Regulated mode before any real data. Named users before assigned scopes. Patient or matter scopes before import. PHI or privilege labels before evidence use. OCR confidence threshold held at 95% unless a customer-approved policy change is documented. Support bundles redacted by default. Cloud AI off unless explicitly approved by the customer — the default pilot path is local-only. Named professional approval required before export.

05

Build sequence — Z1 through Z21

The internal release-candidate build sequence ran in twenty-one numbered sessions. Each added a specific control surface or evidence artifact. None added autonomous decisioning. The list below is the changelog stripped to its operational nouns.

Z1Validation & stabilization. Baseline regression and stabilization pass.
Z2Regulated authentication. Local session model and named-user posture.
Z3Signed update / USB hardening. Trusted release keys, rollback checks, media verification.
Z4Golden-case regression harness. Curated cases used for regression, not certification.
Z5Onboarding & retrieval plan. Enterprise polish and pilot intake.
Z6Controlled folder ingestion. Approved import paths, labels, and intake provenance.
Z7Governed external connectors. Connector framework, disabled and dry-run by default.
Z8Retrieval engine scaffold. Local deterministic retrieval; optional Qdrant seam.
Z9Local LLM via Audit Proxy. Single governed path; no direct app-to-LLM call.
Z10Appliance installer & OS hardening. Hardening profiles, systemd units, hardening check.
Z11Enterprise identity connectors. Identity-provider framework scaffolding.
Z12Physician / attorney workflow templates. Prior auth, appeals, chronology, matter memo.
Z13Professional packet export. Evidence appendix, audit envelope, manifest, checksums.
Z14Backup / restore / support bundle. Admin operations with redaction by default.
Z15Pilot readiness pack. Demo scripts, SOPs, data-handling checklist, role worksheet.
Z16Performance & hardware profiling. Pilot baseline runbook and hardware sizing guide.
Z17Security abuse-case hardening. Documented abuse cases and mitigations.
Z18Compliance evidence binder. Control mappings for HIPAA-style, ISO 42001-style, NIST AI RMF-style review.
Z19Local metrics dashboard. Local-only operational metrics; no external telemetry.
Z20Release-candidate freeze. Frozen artifact manifest and release notes.
Z21First-pilot configuration packs. Synthetic physician and law-firm templates; success criteria.
