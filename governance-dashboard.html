Draft workspace: cited, marked, and explicitly not final.

The draft is presented as a controlled working document. Every material statement carries an inline citation badge linked to the retrieved evidence set. Unsupported claims cannot appear without flagging.

Citation gates

Every material claim in the draft is mapped to a source. Claims without supporting evidence are blocked from the draft and placed in the exception queue. Reviewers see which claims passed and which were withheld.

Explicit draft status

The system cannot finalize its own output. "Draft" is a system state, not a label. No submission-ready document can be produced without a named human reviewer clearing the human gate.

Exception queue: problems the system surfaces, not hides.

Rather than generating confident-sounding text when evidence is missing, Sentinel Node surfaces exceptions for staff resolution. The queue shows what needs attention before review can proceed.

Exception Queue — 3 items requiring resolution
⚠
Citation gap: Claim about prior denial history cannot be sourced.
Resolution: staff to locate denial history or remove claim from draft.
Open
📄

Open
🔒

Operational principle: an exception queue is not a failure state. It is the system working correctly. Surface uncertainty early; resolve it with humans before regulated output leaves the practice.

Human gate and audit trail: every action is logged locally.

Sentinel Node maintains a reviewable local audit trail. Every query, retrieval event, draft generation, reviewer action, and export is recorded in sequence — never sent to cloud logging services.

Audit Log — Session 2025-12-09
09:14:01 Task opened: Prior Auth Support / Patient 4412-B J. Torres (staff)
09:14:02 Retrieval initiated — 3 corpora queried locally system
09:14:05 7 chunks retrieved — 4 accepted (conf ≥0.75) — 3 below threshold system
09:14:08 Draft generated — 1 citation gap flagged — draft held pending review system
09:19:44 Draft reviewed — exception acknowledged — citation gap note added M. Kim (RN)
09:22:17 Draft approved — signed — audit envelope exported to local record Dr. R. Patel

What the audit envelope contains

  • Original query text
  • Corpus list at time of retrieval
  • Full retrieval set with confidence scores
  • Draft as presented to reviewer
  • All exceptions flagged by system
  • Reviewer identity and action
  • Approval timestamp and final status
  • Export hash for integrity verification

The audit envelope is generated locally and stored in the practice's own record system. No telemetry leaves the appliance. The chain of custody is owned by the practice, not by Pocono AI.

Policy boundary: what the appliance will and will not do.

Sentinel Node operates within an explicit authorization scope. The interface surfaces this scope as a visible operational constraint — not fine print, not a disclaimer buried in documentation.

✓ Within scope

  • Evidence retrieval from approved local corpora
  • Cited draft generation for human review
  • Prior authorization support documents
  • Denial response drafting
  • Policy and protocol lookup
  • Chart summary for staff use
  • Document gap identification
  • Audit envelope generation

⛔ Outside scope — system will not execute

  • Definitive clinical diagnosis
  • Autonomous submission to payers
  • Legal advice or opinion
  • Output generation without human gate
  • Retrieval from external or cloud sources
  • Patient communication drafting without physician review
  • Prescribing or treatment recommendations
  • Any output classified as regulatory submission
Design rationale: the boundary is not a liability hedge. It is an operational design choice. Buyers should be able to explain what the system does and does not do to their compliance officer, their malpractice carrier, and their patients. The boundary makes that possible.

Approval state reference.

Every draft in Sentinel Node carries a single current state. Reviewers always know where a work item stands.

Draft

Evidence gathered

Generated content exists and is cited, but is explicitly not final. Staff can read, revise, or route for licensed review.

Next action: route to reviewer

Flagged

Exception pending

One or more citation gaps, stale documents, or policy boundary issues require staff resolution before review can proceed.

Next action: resolve exceptions

Blocked

Citation gate failed

A required claim has no supporting evidence. The output is withheld from the draft. Reviewer cannot approve without resolution.

Next action: locate source or remove claim

Escalated

Physician required

Staff reviewer has determined the item requires licensed clinical judgment. Routed to physician queue without staff resolution.

Next action: physician review

Approved

Human signed

A named licensed professional has approved the draft. Approval is attributed, timestamped, and added to the local audit envelope.

Next action: export / submit / file

Rejected

Not usable

Reviewer has rejected the draft. Rejection reason is logged. A new task can be initiated with revised parameters or additional source documents.

Next action: new task or corpus update
