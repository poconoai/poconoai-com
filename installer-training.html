Installer Training: Deployment, Local Controls, and Handoff Readiness

For Pocono AI deployment staff, technical partners, implementation partners, and MSPs when acting as installers.

Installer Training is separate from Customer Training. Customer staff are not expected to perform installer responsibilities. Installers are not clinical or legal reviewers. These are distinct roles with distinct training requirements.

Roles

Who This Training Is For

Installer Training is not Customer Training. These tracks are separate by design. Installers configure the system. Customers learn to use it safely. Neither role performs the other’s responsibilities during the pilot.

Pocono AI deployment staff

The primary installer for direct-deployment pilots. Brings the physical appliance, performs installation, verifies local operation, and completes the handoff checklist before handing off to the Practice Administrator.

Technical / implementation partners

Qualified technical partners who deploy the Sentinel Node appliance on behalf of Pocono AI or the practice. Follow the same installer checklist and handoff requirements as Pocono AI direct staff.

MSPs acting as installers

Managed service providers who provide IT support for the practice and perform physical installation or network configuration. MSPs follow the installer track; their regular IT support role is separate from the installer role.

Pre-Install Readiness

Pre-Install Review

No installation begins without a completed pre-install review. The pre-install review is not a sales process. It is a technical readiness gate.

  • Pilot scope confirmed: one workflow, one location, one appliance
  • Practice IT contact identified and briefed
  • Physical location for appliance confirmed and accessible
  • Approved source folders identified and accessible
  • Network requirements reviewed with practice IT
  • No external dependency requirements confirmed with practice
  • Backup and rollback plan documented
  • Reviewer role assigned (not the installer role)
  • Practice Administrator / Pilot Lead identified
  • Training schedule for customer team confirmed
Hardware

Hardware Custody and Physical Placement

Physical placement

  • Appliance is placed in a controlled-access area within the practice
  • Physical access is documented and limited to authorized staff
  • Power, cooling, and connectivity requirements confirmed on-site
  • Hardware serial number and asset tag recorded

Hardware custody

  • Chain of custody documented from delivery to installation
  • Appliance is not shared across locations in v1
  • Hardware removal or replacement follows documented procedure
  • Disposal or return follows Pocono AI data-handling procedure
Network

Local Network Configuration

v1 assumption: single office, single appliance, local network segment. Multi-location deployments require additional planning and are not covered by the v1 installer track. Do not assume a v1 installer checklist applies to multi-location deployments.

Network assumptions

  • Appliance operates on the practice local network
  • VLAN and firewall configuration reviewed with practice IT
  • Outbound egress rules configured to prevent routine external data transfer
  • No routine cloud API calls during inference (local model only)

No-egress verification

  • Packet capture or egress monitoring run during test inference
  • Zero outbound data transfer to external AI services confirmed
  • External service exceptions (update channels) documented if present
  • Egress verification result logged in installer handoff record
Approved Sources

Approved Source Folders and Ingestion

Ingestion setup

  • Approved source folders defined and confirmed with Practice Administrator
  • Ingestion path is local — no external data transmission
  • OCR and quality gate configured and tested
  • Unreadable documents are refused or flagged, not silently skipped
  • Ingestion audit log verified before pilot use

Source custody

  • Only approved, in-scope records are ingested
  • Scope is defined per pilot workflow, not open-ended
  • Out-of-scope document rejections are visible and logged
  • Practice staff understand what is and is not in scope
Local-Only Verification

Model, Retrieval, and No-External-Dependency Audit

The installer is responsible for verifying that the system operates locally before pilot use begins. This is not a customer responsibility.

Local model runtime

On-premises model is loaded and functional. No cloud inference API is called during normal operation. Model version and configuration are documented.

Retrieval engine

Vector database is populated from approved local sources. Hybrid search (dense + sparse) is verified on a test query. Access control is confirmed at the retrieval layer.

Audit proxy

Audit Proxy is functioning. Every test query generates a logged entry in the reviewable audit trail. Hash-chain integrity verification arrives with the Stage 2 audit-layer.

No external dependency audit

Active scan for external API calls, remote logging, cloud model endpoints, or undisclosed telemetry. Result documented and signed in installer record.

Backup and rollback

Backup procedure confirmed. Rollback path documented. Rollback capability tested if practical before go-live.

Update path

Software update mechanism understood. Update process documented. Update policy aligned with practice IT requirements.

Audit Log

Audit Log Verification

The audit log must be verified before pilot use begins. An installation without a confirmed audit log is not a completed installation.
  • Audit log is writing entries during test queries
  • Reviewable audit log active on test sequence (hash-chain integrity: Stage 2)
  • All required fields are present per entry (user, timestamp, scope, prompt hash, retrieval IDs, response hash, verification flags)
  • Log retention policy confirmed and configured
  • Log is stored locally, not transmitted externally
  • Log is readable by the Practice Administrator and Responsible Reviewer
  • Log is append-only and reviewable today; Stage 2 hash chaining makes any edit break the chain
  • Audit log sample reviewed and signed in installer record
Day Zero / Day One

Day Zero and Day One Validation

Day Zero (installer)

  • Hardware placed and powered
  • Network configured and egress verified
  • Source folders ingested
  • Local model confirmed operational
  • Retrieval confirmed on test query
  • Audit proxy confirmed logging
  • No-external-dependency audit passed
  • Audit log sample verified
  • Go/no-go checklist completed and signed

Day One (installer confirms, customer begins)

  • Practice Administrator briefed on system status
  • Approved source set confirmed with Practice Administrator
  • Customer Training session scheduled or completed
  • First test packet run with Practice Administrator present
  • Installer available for Day One support queries
  • Escalation path to Pocono AI technical support confirmed
  • Installer handoff document signed by Practice Administrator
Handoff

Handoff to Customer Training and Pilot Lead

The installer’s role ends at handoff. The Practice Administrator / Pilot Lead owns the pilot from that point.

Installer delivers to Practice Administrator

  • Completed installer checklist
  • Audit log sample and verification result
  • Egress verification result
  • Approved source folder documentation
  • Software version and configuration record
  • Escalation contacts for technical support
  • Signed installer handoff document

Practice Administrator confirms

  • Understands system scope and approved sources
  • Customer Training session completed or scheduled
  • Responsible Reviewer identified and briefed
  • Pilot friction log owner named
  • Pilot metrics baseline established
  • Escalation path confirmed
Installer Checklist

Installer Go/No-Go Checklist

All items must be completed and documented before pilot use begins. Incomplete items block go-live.

  • Pre-install review completed and documented
  • Hardware placed, powered, and chain of custody logged
  • Network configured: VLAN, firewall, egress rules
  • Egress verification: zero outbound AI inference confirmed
  • Approved source folders defined and ingested
  • OCR and quality gate tested
  • Local model operational: version and config documented
  • Retrieval engine verified: test query returns expected results
  • Audit Proxy confirmed: logging active on test queries
  • Reviewable audit log active on test log sequence (hash-chain integrity: Stage 2)
  • No-external-dependency audit passed and documented
  • Backup and rollback path documented
  • Update path documented
  • Practice Administrator briefed on system status
  • Customer Training completed or formally scheduled
  • Installer handoff document signed
  • Escalation path to Pocono AI technical support confirmed
  • Go/no-go decision: Approved for pilot use
