Governance Doctrine · Refusal & Containment

How Pocono AI fails safely.

Every AI system fails. The honest question is what happens when it does. This page documents how Sentinel Node is designed to fail — by refusing, escalating, flagging, and stopping — rather than by silently producing wrong work that a licensed professional then has to defend.

The premise: AI in regulated industries does not get to fail like consumer AI fails. A wrong chatbot answer at home is annoying. A wrong cited paragraph in a court filing is a bar complaint. A wrong dosing recommendation in a clinical note is a malpractice case. Sentinel Node is designed so that when the model is uncertain, the failure mode is visible refusal — not invisible confabulation.

The six ways Sentinel Node refuses to fail silently.

Each represents a specific class of AI failure and the corresponding containment mechanism.

Citation Verification

Failure mode: Hallucinated case law, fabricated quotes, invented page numbers.

This is the well-known failure mode — the one that produced public sanctions in Mata v. Avianca and several similar cases since 2023. A cloud LLM confidently cites a case that does not exist. The attorney, trusting the output, files it. The court catches it.

Sentinel Node does not source citations from a generative model's parametric memory. It sources them from a sealed retrieval index built from documents the firm explicitly uploaded. Every cited quotation is bound to a clickable source path. Every quote is verified against the underlying document before display. When the retrieved text differs from the AI's paraphrase — even subtly — both versions are shown side by side and the attorney chooses.

Cloud LLM failure

"As established in Riley v. Patterson, 412 F.3d 287 (3d Cir. 2010), the moving party..." — the case doesn't exist.

Sentinel Node behavior

"Retrieved 3 cases on this issue from firm precedent library. Top match: Cordero v. Brookfield Transport (Monroe County, 2019) — click to verify." No retrieval, no claim.

Out-of-Scope Refusal

Failure mode: AI generates output the firm's governance policy excludes.

Many firms have informal positions on what they will and won't allow AI to do. Most never operationalize them. The result: an associate working at 11 PM uses ChatGPT to draft a motion because nothing was stopping them.

Sentinel Node enforces the firm's governance policy as configuration, not as suggestion. If the policy says "no AI-drafted motions, briefs, or pleadings," the system refuses those requests at the system level, with the refusal reason cited back to the policy document and the policy author. The refusal is logged in the audit chain — including who tried, when, and what.

user.prompt: "Draft a motion to dismiss in Halverson" ↓ policy.check: firm_governance_policy.v3 (uploaded D.Walsh 2024-11-08) ↓ rule_match: § 4.2 — AI-drafted advocacy excluded ↓ RESPONSE: DECLINED audit.envelope: attempt logged · user · timestamp · policy version suggested.alternatives: evidence retrieval · case law lookup · clause analysis

Uncertainty Flagging

Failure mode: The model is unsure, but the output reads as confident.

A core danger of LLMs is that fluency masks uncertainty. The same model that knows the answer and the model that is guessing produce sentences of equal smoothness. This is the user-experience layer where most damage happens.

Sentinel Node attaches a confidence band to every substantive output. If the retrieval returned no strong matches, the system says so. If OCR confidence on a scanned exhibit is below threshold, the original image is shown inline and the AI does not pretend to know what it says. "I don't know" is a first-class output, not a failure mode.

Confident hallucination

"The handwritten interim order specifies supervised visitation under terms set forth in the substance abuse treatment provision."

Honest uncertainty

"⚠ OCR low confidence. Original scanned image displayed below. Please read directly — system cannot reliably parse this handwriting."

Mandatory Attorney Review

Failure mode: AI output exits the firm without a licensed reviewer.

Regardless of how confident the model is, regardless of how routine the document is, regardless of how late it is or how rushed the attorney is, regulated outputs do not leave the building without a named attorney's signoff. This is enforced at the workflow level. There is no "skip review" button.

Each output sits in a review queue until an attorney with the appropriate role approves it. The approval is sealed into the audit envelope with the attorney's identity, the version reviewed, the decision (approve / send back / discuss), and any review notes. If a document moves to client delivery, the audit envelope follows it.

workflow.stage: AI draft generated ↓ review.queue: assigned to reviewing attorney (per matter assignment) ↓ [ attorney review — required ] ↓ APPROVE → audit envelope sealed → output released SEND BACK → audit envelope sealed → returns to draft state REJECT → audit envelope sealed → matter flagged for partner

Privilege Boundary Enforcement

Failure mode: Work product touches infrastructure outside the firm's control.

This is the architectural failure cloud AI cannot solve. Any system that sends work product through an external API has, by definition, exposed that work product to a third party. Whether that exposure breaks privilege under ABA Model Rule 1.6 is a question reasonable lawyers debate; whether it adds malpractice surface area is not.

Sentinel Node is an on-premise physical appliance. No prompt, no retrieval, no draft, no audit envelope leaves the firm's network. There is no telemetry. There is no "anonymized usage data" sent home. There is no cloud failover. If the firm loses internet, Sentinel Node still works. If Pocono AI as a company ceased to exist tomorrow, the appliance continues operating against the firm's own data.

Cloud AI architecture

Prompt → vendor API → third-party model host → response. Privilege exposure surface: every hop. Audit trail: vendor-controlled.

Sentinel Node architecture

Prompt → local appliance → local model → local response. Privilege exposure surface: zero hops outside the firm. Audit trail: firm-owned.

Append-Only Audit Chain

Failure mode: Months later, no one can reconstruct what the AI did or why.

When something goes wrong — a malpractice carrier asking questions, a bar complaint, opposing counsel demanding discovery on AI-assisted work product — the question is not "did you have AI involved?" It's "can you produce the exact retrieval, the exact draft, the exact reviewer, the exact decision, on the exact version, at the exact time?"

Sentinel Node produces a sealed audit envelope for every substantive AI interaction. Each envelope contains the prompt, the retrieved sources, the generated draft, the reviewing attorney, the review decision, and the final version. Each envelope is recorded in a reviewable local audit trail. The next audit-layer release (Stage 2) cryptographically links each envelope to the previous one. The record is local, reviewable today and tamper-evident next, and the firm's property — not the vendor's.

envelope_id: env_2026-03-04_14:17:08Z_a7f3e1b8c9d4... prompt: "Find every document referencing the modified delivery..." sources: 23 documents retrieved (Bates-stamped citations attached) draft: evidence summary v1.0 reviewer: S. Mendez (signed: 2026-03-04 17:34:12Z) decision: approved with edits → v1.1 prev_hash: env_2026-03-04_14:12:55Z_b8c4f2a1... next_hash: env_2026-03-04_14:18:33Z_c9d5e3b2... SEALED. APPEND-ONLY. QUERYABLE.

Pocono AI's Doctrine of Refusal

  • Refusal is a feature. Saying "I don't know" or "I won't do that" preserves more value than smooth, wrong output ever could.
  • Confidence must be earned per citation. Every quoted source is verified against the underlying document before display. Paraphrases are flagged as paraphrases.
  • Governance is configuration, not aspiration. What the firm decides AI can and cannot do is enforced at the system level — not posted on a wall.
  • The reviewer is always a person. There is no automated path from AI draft to client delivery. Human-in-the-loop is structural, not optional.
  • The chain is the firm's. Audit envelopes are local, append-only, and survive vendor disappearance.
  • Silent failure is the only unacceptable failure. Loud failures — refusals, escalations, flags, uncertainty bands — are the system working as designed.

The line we will not cross.

What "fail safely" actually rules out.

AI should never silently act inside a law firm or a medical practice. That is the line. We do not build systems that take autonomous action on regulated work. We do not build agentic loops that send communications, file motions, or update records without a named professional reviewing and approving each action.

When you hear vendors describe AI agents that "handle the entire intake," "draft and file routine motions," or "autonomously respond to client communications" — those are systems built to fail silently. Errors compound inside automation loops where no human sees them until the harm is done.

Sentinel Node is built on the opposite premise: the AI does the document work; the attorney does the lawyering. When in doubt, the system stops and asks. That stop, on purpose, is what makes the system safe to deploy in a setting where mistakes cost more than time.
